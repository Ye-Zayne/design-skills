# 示例任务

把以下描述中的品牌、内容和技术约束替换为你的实际项目。支持显式调用 Skill 的客户端，可使用其调用方式；其他工具可参考 `SKILL.md`，并明确让助手遵循其中的设计指导。

## 产品落地页

```text
使用 frontend-design，为一个团队知识检索产品实现落地页。
受众：第一次了解产品的中小团队负责人。
目标：让用户理解“用自然语言查找团队资料”，并找到预约演示入口。
风格：清晰、轻盈，有编辑感的文字排版，采用一套一致的强调色。
内容：价值主张、三项核心能力、工作流程、客户评价占位区、常见问题。
技术：沿用当前项目的框架与样式方案，不新增组件库。
约束：不得虚构客户、数据或评价；缺失的内容使用明确占位文案。
完成响应式页面，并检查键盘操作、焦点样式和减少动态效果设置。
```

## 个人作品集

```text
使用 frontend-design，改版当前项目的个人作品集首页。
受众：招聘负责人和潜在合作方。
目标：让读者快速理解我的专业方向，并浏览三个代表项目。
风格：以真实作品为主体，使用克制的排版和明确的项目索引。
内容：简短介绍、三个项目卡片、工作方法、联系方式。
技术：保留现有路由、组件库和部署方式。
约束：使用我提供的经历和项目资料，不虚构公司、奖项或项目指标。
图片缺失时保留有说明的占位区域，不用无关图片替代作品。
兼顾桌面、手机和键盘操作，链接目的清楚可辨。
```

## 业务数据看板

```text
使用 frontend-design，改善当前项目的数据看板。
受众：每天查看经营指标的运营人员。
目标：让用户能找到异常趋势、筛选日期、查看明细。
风格：高信息密度，清晰层级，颜色只用于状态和重点。
内容：关键指标、趋势图、筛选区、明细表、加载/空数据/错误状态。
技术：沿用现有组件库和图表库，不引入额外 UI 依赖。
约束：保持现有数据接口与交互逻辑，示例数据须明确标注。
不要只用颜色区分状态；提供文字或图标说明。
先说明要改动的页面和交互，再实现并验证主要操作。
```

## 补充信息清单

提交任务时，尽量提供：

- 要创建或修改的页面、组件和路径。
- 目标用户、关键操作和核心信息。
- 框架、现有组件库、允许新增的依赖。
- 品牌规范、参考图和需要保持的设计要素。
- 已确认文案、图片、真实数据与占位内容的边界。
- 设备尺寸、可访问性和性能要求。
